Two Improvement Systems
①
Foundation Model — a better model (Centaur)

A foundation model fine-tuned on the canonical behavioral records (Binz et al. 2024). Improvement is encoded in weights, learned from outcome data and shared cross-tenant. This is the model getting smarter about human behavior.

②
Method Optimization Loop — a better method (prompts)

A separate, data-driven search over how we use the model — prompting is the first example. Propose a config → score on held-out ledger data → Ladder-gate → accept. Improvement is a gated config artifact, per-tenant. Same discipline as Part I's search loop — independent of the foundation model.

•
Experimental Enrichment Axis (cross-cutting)

Task decomposition + contextualization, brought into the prompting and/or the Centaur inputs as a possible enrichment. A distinct experimental direction — tested, not assumed — that can lift either branch.

Guardrails & Evaluation

5-step update gate: shadow eval (≥1k preds) → Blum-Hardt η lift test → reliability ceiling (finite-n cap) → PSI drift check → human sign-off for fine-tune ships · auto-rollback on TVD +2σ · 30-day version retention
